## 2. Hallazgos Adicionales de Auditoría en Código/Documentación Existente

1. **Discrepancia documental menor detectada en [README.md](../README.md#L155)**:
   - La línea 155 de `README.md` indicaba *"Validar que la respuesta contenga `verdict: 'ATTESTED_VALID'`"*; al auditar `authority-service.mjs:370-407` se comprobó que `finalResponse` emite `schemaVersion: '1.0'`, `authorityType`, `signature`, `attestationPayloadSha256` (no posee campo `verdict`). Queda documentado aquí como hallazgo no bloqueante para futura limpieza del README en su checklist operativo.
2. **Separación de firma KMS en AWS vs GCP**:
   - `ProductionKmsSigningProvider` firma `Buffer` de payload canónico UTF-8. Tanto GCP `EC_SIGN_ED25519` como AWS `ECC_NIST_EDWARDS25519` (`ED25519_SHA_512` + `MessageType: 'RAW'`) esperan el payload crudo sin pre-hashing (`PureEdDSA`), lo cual alinea correctamente con `signing-providers.mjs:328-336` — pero el adaptador SDK debe enviar el mensaje crudo y nunca pre-hashearlo con SHA-256.
